01
Población vs. Muestra
Parámetro vs. Estadístico — La base de toda inferencia

Antes de poder hacer afirmaciones sobre un grupo enorme a partir de un puñado de datos, necesitamos entender la relación entre el todo (la población) y la parte (la muestra). Este es el punto de partida de toda la analítica inferencial.

¿Por qué no analizamos todo?

En el mundo real es imposible o carísimo estudiar a todos los individuos. Si un banco tiene 10 millones de clientes, no va a llamar a cada uno para preguntarle su nivel de satisfacción. En vez de eso, extraemos una muestra aleatoria y usamos sus datos para inferir (adivinar de manera educada) cómo se comporta el universo total.

Población (Parámetro)

Es el universo completo de individuos o elementos que nos interesa estudiar. La métrica que calculamos sobre la población se llama Parámetro y casi siempre es desconocido. Se representa con letras griegas.

μ = media poblacional   |   σ = desviación estándar poblacional

Ejemplo: El salario promedio real de TODOS los 10 millones de clientes del banco. Es un número fijo que existe, pero que no conocemos.

Muestra (Estadístico)

Un subconjunto representativo seleccionado de la población. La métrica que calculamos sobre ella se llama Estadístico — es lo que obtenemos con Python o Excel. Se representan con letras latinas.

x̄ = media muestral   |   s = desviación estándar muestral

Ejemplo: El salario promedio de los 5,000 clientes que seleccionamos al azar. Es nuestro mejor estimado del parámetro.

Mundo Real

Encuestas Electorales

Cuando ves en las noticias: "El candidato A tiene el 52% de intención de voto con un margen de error de ±3%", ¡eso es inferencia estadística en acción! La encuestadora no habló con los 39 millones de votantes colombianos (la población), sino con una muestra de ~1,200 personas. El 52% es un estadístico, y lo usan para estimar el parámetro (el verdadero porcentaje de toda la población).

Mundo Real

Control de Calidad en Fábricas

Una fábrica de tornillos produce 500,000 unidades al día. ¿Van a revisar cada uno? Imposible. En su lugar, toman una muestra de 200 tornillos al azar cada hora y miden su diámetro. Si el promedio muestral (el estadístico) se desvía demasiado del diámetro ideal (el parámetro), detienen la producción.

02
Muestreo Aleatorio y Error de Muestreo
La diferencia inevitable entre la muestra y la realidad

Como vimos en el código, la media de la muestra no es exactamente igual a la media de la población. ¿Es un error? No es un error humano — es algo completamente natural llamado error de muestreo.

Muestreo Aleatorio

Es la técnica de seleccionar una muestra donde cada miembro de la población tiene la misma probabilidad de ser elegido. Es fundamental para garantizar que nuestra muestra no esté sesgada.

⚠️

Sesgo de selección

Si solo encuestamos a clientes que vienen a la sucursal bancaria del barrio rico, nuestras conclusiones sobre todos los clientes serán completamente sesgadas.

Error de Muestreo

Es la diferencia inevitable entre el estadístico (x̄) y el parámetro (μ). No es un error humano, sino una consecuencia de la variabilidad natural. Si tomas otra muestra de 500 clientes, obtendrás una media ligeramente diferente.

Error de Muestreo = x̄ − μ
🤔

Pero espera… si no conozco μ, ¿cómo calculo ese error?

¡Exacto! En la vida real nunca conocemos μ — si lo conociéramos, no necesitaríamos tomar muestras. Nosotros podemos calcularlo aquí porque estamos tratando nuestro dataset completo (credit_risk_data.csv) como si fuera la "población" para fines de aprendizaje. En un caso real, el error de muestreo existe pero es desconocido. Precisamente por eso se inventaron los intervalos de confianza (que veremos más adelante): son la herramienta que nos permite estimar qué tan grande podría ser ese error, sin necesidad de conocer μ.

Mundo Real

Netflix y las Pruebas A/B

Cuando Netflix quiere saber si un nuevo diseño de portada genera más clics, no lo muestra a sus 260 millones de usuarios. Le muestra la portada nueva a una muestra aleatoria (ej. 50,000 usuarios) y la vieja a otra muestra similar. Compara las tasas de clic. La diferencia entre muestras incluye un inevitable error de muestreo — por eso Netflix necesita herramientas estadísticas (como las que veremos más adelante) para determinar si la diferencia es "real" o simplemente azar.

python — múltiples_muestras.py
# Demostrar que cada muestra da un estadístico diferente import pandas as pd import numpy as np import matplotlib.pyplot as plt df = pd.read_csv('credit_risk_data.csv') # Databricks: df = spark.table('credit_risk_data').toPandas() mu = df['puntaje_credito'].mean() # Tomar 10 muestras diferentes de n=200 medias = [] print(f"Parámetro real (μ): {mu:.2f}") print("-" * 45) for i in range(10): x_bar = df['puntaje_credito'].sample(n=200).mean() medias.append(x_bar) error = x_bar - mu print(f"Muestra {i+1:2d}: x̄ = {x_bar:.2f} | Error = {error:+.2f}") # Visualizar: cada punto es una media muestral # La línea roja es μ. Observa cómo los puntos "orbitan" alrededor. plt.figure(figsize=(10, 3)) plt.scatter(medias, range(1, 11), color='#c05621', s=100, zorder=3) plt.axvline(x=mu, color='red', linestyle='--', linewidth=2, label=f'μ real = {mu:.2f}') # Dibujar líneas horizontales del error de cada muestra for i, m in enumerate(medias): color = '#2a7d5f' if abs(m - mu) < 5 else '#b5334a' plt.hlines(i+1, mu, m, colors=color, linewidth=2, alpha=0.6) plt.xlabel('Puntaje de crédito promedio') plt.ylabel('# de muestra') plt.title('Cada muestra da un x̄ diferente (los errores son las líneas)') plt.legend() plt.grid(axis='x', alpha=0.3) plt.tight_layout() plt.show()

03
La Ley de los Grandes Números (LGN)
La estabilidad que surge del caos

El Principio de Convergencia

Aunque un evento individual es impredecible (¿sale 1 o 6 al lanzar un dado?), el comportamiento promedio de una multitud de eventos se vuelve sorprendentemente predecible. La LGN dice que a medida que el tamaño de tu muestra (n) crece, el valor de tu estadístico (x̄) se acerca cada vez más al parámetro verdadero (μ).

☕

En palabras simples: pocos datos = no te fíes. Muchos datos = puedes confiar.

Imagina que le preguntas a 3 personas en la calle si les gusta el café. Puede que las 3 digan que no. ¿Eso significa que a nadie le gusta el café? No — simplemente tuviste mala suerte con esas 3. Pero si le preguntas a 10,000 personas, ya no hay "mala suerte" que valga. Los que dicen sí y los que dicen no se van acomodando, y el porcentaje que obtienes se acerca mucho a la realidad de toda la población.

En términos prácticos: la LGN es la razón por la que más datos = mejor estimación. Te garantiza que si tomas una muestra lo suficientemente grande, tu estadístico (x̄) va a estar muy cerquita del parámetro real (μ).

💡

El "Efecto de Cancelación" del Azar

Con una muestra enorme, los resultados extremos o raros se diluyen entre la gran cantidad de valores comunes. Una muestra pequeña es un bote en una tormenta (muy inestable). Una muestra grande es un transatlántico (muy estable).

Casinos

Un casino no sabe si TÚ ganarás esta noche, pero sabe que en promedio gana $0.05 por cada $1 apostado. Con miles de apuestas diarias, la LGN garantiza su ganancia.

Seguros

Una aseguradora no sabe si TÚ chocarás tu carro, pero sabe con precisión qué porcentaje de sus millones de clientes lo hará. Eso les permite calcular primas rentables.

Marketing

Si envías un email a 50 personas, la tasa de apertura puede ser 10% o 60% por azar. Pero si lo envías a 50,000, la tasa será predeciblemente estable (~25%).

Simulador Interactivo: Ley de los Grandes Números

Lanza un dado, anota el resultado y mira cómo el promedio acumulado de todos tus lanzamientos converge a 3.5.

🎲 ¿Qué estamos haciendo aquí?
Imagina que lanzas un dado y anotas el resultado: 4. Lanzas de nuevo: 2. Otra vez: 6. Otra: 1...
Después de cada lanzamiento, calculas el promedio de TODOS los resultados que llevas hasta ahora.

¿Hacia dónde debería converger ese promedio?
Un dado justo tiene 6 caras con igual probabilidad. Si lo lanzaras infinitas veces, saldrían la misma cantidad de 1s, 2s, 3s, 4s, 5s y 6s. El promedio de todos esos resultados sería:
(1 + 2 + 3 + 4 + 5 + 6) ÷ 6 = 3.5
Esto se llama el valor esperado: el promedio teórico al que converge tu promedio real si lanzas suficientes veces.

¿Qué demuestra la LGN? Que con pocos lanzamientos (5, 10) tu promedio puede ser cualquier cosa (2.3, 4.8...). Pero con muchos lanzamientos (500, 1000) se estabiliza inevitablemente en 3.5. ¡Pruébalo tú mismo!

La Distribución Muestral
La "Huella Digital del Azar" — La idea más importante de la inferencia

La LGN nos dijo que muestras grandes son mejores. Pero en la vida real a menudo estamos "atrapados" con una sola muestra. La pregunta crucial es: si tomara otra muestra, ¿qué tan diferente sería su resultado?

El Experimento Mental: La "Fábrica de Muestras"

Imagina una máquina que hace esto una y otra vez:

1️⃣ Extraer: Toma una muestra aleatoria de tamaño n (ej. 100 clientes).

2️⃣ Calcular: Calcula la media de puntaje de crédito de esa muestra. Anota el resultado.

3️⃣ Repetir: Devuelve esos clientes y repite el proceso 2,000 veces.

Al final tenemos 2,000 medias muestrales diferentes. Si hacemos un histograma de esas medias, eso es la Distribución Muestral de la Media.

🗺️

¿Por qué importa?

La distribución muestral es el mapa que nos permite ubicar nuestra única muestra en el universo de todas las muestras posibles. Nos dice qué valores de x̄ son comunes, cuáles son raros y cómo se agrupan alrededor de la verdadera media μ.

python — distribucion_muestral.py
import pandas as pd, numpy as np, matplotlib.pyplot as plt import seaborn as sns df = pd.read_csv('credit_risk_data.csv') # Databricks: df = spark.table('credit_risk_data').toPandas() mu = df['puntaje_credito'].mean() # La "Fábrica de Muestras": tomar 2000 muestras de n=100 n_muestras = 2000 n_tamaño = 100 medias = [df['puntaje_credito'].sample(n=n_tamaño).mean() for _ in range(n_muestras)] # Visualizar la distribución muestral fig, axes = plt.subplots(1, 2, figsize=(14, 5)) # Izquierda: Distribución de la POBLACIÓN (puede ser rara) axes[0].hist(df['puntaje_credito'], bins=50, color='#c05621', alpha=0.7) axes[0].set_title('Distribución de la POBLACIÓN') axes[0].set_xlabel('Puntaje de Crédito') # Derecha: Distribución MUESTRAL (¡campana!) axes[1].hist(medias, bins=40, color='#6d4aaa', alpha=0.7, edgecolor='white') axes[1].axvline(mu, color='red', linestyle='--', label=f'μ = {mu:.2f}') axes[1].set_title(f'Distribución MUESTRAL de x̄ (n={n_tamaño})') axes[1].set_xlabel('Media muestral (x̄)') axes[1].legend() plt.tight_layout(); plt.show() print(f"Media de las 2000 medias muestrales: {np.mean(medias):.2f}") print(f"Media poblacional real (μ): {mu:.2f}")

El Teorema del Límite Central (TLC)
La joya de la corona de la estadística

El "Milagro" del TLC

Si el tamaño de la muestra (n) es suficientemente grande (generalmente n > 30), la distribución muestral de la media será aproximadamente una distribución Normal (campana de Gauss), ¡sin importar cómo sea la distribución original de la población!

X̄ ~ N(μ, σ/√n)   cuando   n → grande
💡

¿Por qué es tan poderoso?

Porque si sabemos que la distribución de las medias muestrales sigue una campana de Gauss, podemos usar todas las propiedades de la distribución normal para calcular probabilidades, construir intervalos de confianza y hacer pruebas de hipótesis. No importa si tus datos originales tienen forma de montaña, de U, o son completamente planos.

Intervalos de Confianza
Por qué adivinar un solo número siempre sale mal

Si un gerente pregunta "¿cuál es el puntaje de crédito promedio de nuestros clientes?", responder con un solo número (648.53) es ser precisos pero probablemente incorrectos. Los intervalos de confianza resuelven esto: en vez de un punto, damos un rango de valores plausibles.

La Lanza

Estimación Puntual

Dar un solo número: "El promedio es 648.53". Es como lanzar una lanza al agua. Tienes que ser increíblemente preciso para darle al pez. Casi siempre te equivocas por un poco. No dice nada sobre cuánta incertidumbre tienes.

La Red

Estimación por Intervalo

Dar un rango: "Está entre 635 y 652". Es como lanzar una red de pesca. Asumes un margen de error, pero garantizas con una probabilidad alta que atrapaste la verdad poblacional dentro del rango.

⚠️

El Mito del 95% de Confianza — ¡Cuidado!

Error común: "Hay un 95% de probabilidad de que μ esté dentro de mi intervalo".
Realidad: μ es un número fijo (no se mueve, no tiene probabilidad). La confianza del 95% significa que si repites el estudio 100 veces, 95 de las redes (intervalos) atraparán a μ y 5 fallarán. Es la confianza en el método, no en un intervalo particular.

Anatomía del Intervalo

La Fórmula Intuitiva

Intervalo = Estimación Puntual ± Margen de Error
Margen de Error = (Valor Crítico) × (Error Estándar)

Estimación Puntual: Tu mejor estimado (x̄).
Error Estándar (EE): Mide la variabilidad típica de x̄. Se calcula como: EE = s / √n.
Valor Crítico (z): Cuántos errores estándar necesitas para alcanzar tu nivel de confianza. Para 95% → z = 1.96.

Intervalos de Confianza en la Práctica
Para medias y proporciones con Python

IC para una Media

Se usa para estimar el valor promedio de una variable cuantitativa.

IC = x̄ ± z* × (s / √n)

Ejemplo: Estimar el ingreso promedio de todos los clientes del banco.

IC para una Proporción

Se usa para estimar el porcentaje de una población con cierta característica.

IC = p̂ ± z* × √(p̂(1−p̂) / n)

Ejemplo: Estimar la tasa de morosidad de todos los clientes.

python — intervalos_confianza.py
import scipy.stats as st import numpy as np, pandas as pd df = pd.read_csv('credit_risk_data.csv') # Databricks: df = spark.table('credit_risk_data').toPandas() muestra = df.sample(n=500, random_state=101) # ═══ IC PARA UNA MEDIA ═══ x_bar = muestra['puntaje_credito'].mean() s = muestra['puntaje_credito'].std() n = len(muestra) ee = s / np.sqrt(n) ic_media = st.norm.interval(0.95, loc=x_bar, scale=ee) print("═══ INTERVALO DE CONFIANZA PARA LA MEDIA ═══") print(f"Media muestral (x̄): {x_bar:.2f}") print(f"Error estándar: {ee:.2f}") print(f"IC 95%: ({ic_media[0]:.2f}, {ic_media[1]:.2f})") print(f"Margen de error: ±{1.96*ee:.2f}") # ═══ IC PARA UNA PROPORCIÓN ═══ p_hat = (muestra['estado_pago'] == 'No Pagado').mean() ee_prop = np.sqrt((p_hat * (1 - p_hat)) / n) ic_prop = st.norm.interval(0.95, loc=p_hat, scale=ee_prop) print("\n═══ INTERVALO DE CONFIANZA PARA LA PROPORCIÓN ═══") print(f"Proporción muestral (p̂): {p_hat:.2%}") print(f"IC 95%: ({ic_prop[0]:.2%}, {ic_prop[1]:.2%})") # ═══ EFECTO DEL TAMAÑO DE MUESTRA ═══ print("\n═══ ¿CÓMO AFECTA n AL ANCHO DEL IC? ═══") for n_test in [30, 100, 500, 2000, 10000]: m = df['puntaje_credito'].sample(n=n_test) ic = st.norm.interval(0.95, loc=m.mean(), scale=m.std()/np.sqrt(n_test)) ancho = ic[1] - ic[0] print(f"n={n_test:>5}: IC ancho = {ancho:.2f}")
✅

Tres Factores que Controlan el Ancho del IC

1. Nivel de Confianza ↑ → Intervalo más ancho (más seguridad = red más grande).
2. Tamaño de Muestra (n) ↑ → Intervalo más estrecho (más datos = más precisión).
3. Variabilidad (s) ↑ → Intervalo más ancho (datos más dispersos = más incertidumbre).

Pruebas de Hipótesis
El juicio de los datos — Inocente hasta demostrar lo contrario

Los intervalos de confianza responden: "¿En qué rango está la verdad?". Las pruebas de hipótesis van más allá: nos permiten tomar una decisión. Su lógica es idéntica a un juicio penal: el acusado es inocente hasta que se demuestre lo contrario.

Hipótesis Nula (H₀)

El statu quo / Presunción de inocencia.

Representa que "no hay cambio", "no hay diferencia" o "no hay efecto". Siempre contiene un signo de igualdad (=). Es lo que intentamos refutar.

Tribunal: El acusado es inocente.

Negocio: La nueva web NO vende más que la vieja.

Hipótesis Alternativa (Hₐ)

La acusación del fiscal.

Es lo que tú (como analista) intentas probar con los datos. "¡Sí hay diferencia!", "¡La campaña aumentó las ventas!". Nunca contiene igualdad.

Tribunal: El acusado es culpable.

Negocio: La nueva web SÍ vende más.

⚖️

Regla de Oro

Nunca "probamos" que H₀ es verdadera. Solo podemos: (a) rechazar H₀ porque la evidencia es abrumadora, o (b) no rechazar H₀ porque no tenemos suficiente evidencia. "No culpable" NO es lo mismo que "inocente".

Mundo Real

Prueba A/B en Spotify

Spotify quiere saber si un botón verde genera más suscripciones que uno azul. H₀: No hay diferencia entre los colores. Hₐ: El verde genera más suscripciones. Muestran cada versión a 100,000 usuarios aleatorios y miden la tasa de conversión. Si la diferencia es estadísticamente significativa, rechazan H₀ y adoptan el verde.

El Veredicto: El Valor P
Midiendo la rareza de la evidencia

¿Qué es el p-value?

Responde a esta pregunta: "Si H₀ fuera cierta (el acusado es inocente), ¿cuál es la probabilidad de haber encontrado evidencia tan extrema como la de mi muestra?"

p-value alto (ej. 0.40): "Nada raro. Encontraríamos esta evidencia el 40% de las veces por azar. No rechazamos H₀."

p-value bajo (ej. 0.01): "¡Extremadamente raro! Solo un 1% de chances. La presunción de inocencia no es sostenible. ¡Rechazamos H₀!"

🔑

La Regla de Decisión Dorada

Si p-value < α → Rechazamos H₀. (If the p is low, the null must go!)
Si p-value ≥ α → No rechazamos H₀. (If the p is high, let the null fly!)

Escala Interactiva del Valor P (α = 0.05)

α = 0.05
← p alto (NO rechazas H₀) p bajo (RECHAZAS H₀) →
p = 0.800
El statu quo se mantiene.

Errores Tipo I y Tipo II
Ningún tribunal es perfecto

Así como en un juicio real se puede condenar a un inocente o dejar libre a un culpable, nuestras decisiones estadísticas también pueden ser erróneas.

H₀ es CIERTA
(Inocente)
H₀ es FALSA
(Culpable)
No Rechazar H₀
(Liberar)
Correcto ✅ Liberaste a un inocente
Error Tipo II (β) Dejaste ir al culpable
Rechazar H₀
(Condenar)
Error Tipo I (α) Condenaste a un inocente
Correcto ✅ (Potencia) ¡Atrapaste al culpable!
Error Tipo I

Alarma de incendios suena por una tostada. Evacuaste a todos (rechazaste H₀: "no hay incendio"), pero era una falsa alarma. Perdiste tiempo y dinero.

En negocio: Lanzas una campaña costosa porque tu prueba A/B dijo que el nuevo diseño era mejor, pero NO lo era. Perdiste dinero.

Error Tipo II

La alarma de incendios NO suena durante un incendio real. No rechazaste H₀ ("no hay incendio") cuando debiste hacerlo. Consecuencias graves.

En negocio: Descartaste un fármaco que SÍ funcionaba porque tu ensayo no detectó el efecto. Perdiste una oportunidad.

⚡

Potencia de una Prueba (1 − β)

Es la probabilidad de detectar correctamente un efecto real. Queremos pruebas con alta potencia. Se aumenta con: muestras más grandes, efectos más grandes, o niveles α más altos (pero esto aumenta el riesgo de Error Tipo I).

Pruebas de Hipótesis con Python
Prueba t para medias y Chi-cuadrado para categóricas
Prueba t para Muestras Independientes

Se usa para comparar las medias de dos grupos que no tienen relación. Pregunta de negocio: ¿Existe una diferencia significativa en el puntaje de crédito promedio entre clientes que pagaron y los que no?

H₀: μ_pagado = μ_no_pagado (No hay diferencia)

Hₐ: μ_pagado ≠ μ_no_pagado (Sí hay diferencia)

python — prueba_t_independiente.py
import scipy.stats as st import pandas as pd df = pd.read_csv('credit_risk_data.csv') # Databricks: df = spark.table('credit_risk_data').toPandas() # Separar los dos grupos pagado = df[df['estado_pago'] == 'Pagado']['puntaje_credito'] no_pagado = df[df['estado_pago'] == 'No Pagado']['puntaje_credito'] print(f"Media Pagado: {pagado.mean():.2f}") print(f"Media No Pagado: {no_pagado.mean():.2f}") # Prueba t de Welch (no asume varianzas iguales) t_stat, p_value = st.ttest_ind(pagado, no_pagado, equal_var=False) print(f"\nEstadístico t: {t_stat:.4f}") print(f"Valor p: {p_value:.6f}") alpha = 0.05 if p_value < alpha: print("\n✅ RECHAZAMOS H₀: Hay diferencia significativa.") print("El puntaje de crédito SÍ difiere entre grupos.") else: print("\n❌ NO rechazamos H₀: No hay evidencia suficiente.")
Prueba Chi-Cuadrado (χ²) de Independencia

Se usa para determinar si existe una relación entre dos variables categóricas. Pregunta: ¿El propósito del préstamo está relacionado con si el cliente paga o no?

H₀: Propósito del préstamo y estado de pago son independientes (sin relación)

Hₐ: Propósito del préstamo y estado de pago son dependientes (sí hay relación)

python — prueba_chi_cuadrado.py
import scipy.stats as st import pandas as pd import seaborn as sns, matplotlib.pyplot as plt df = pd.read_csv('credit_risk_data.csv') # Databricks: df = spark.table('credit_risk_data').toPandas() # Tabla de contingencia tabla = pd.crosstab(df['proposito_prestamo'], df['estado_pago']) print("Tabla de Contingencia:") print(tabla) # Test Chi-cuadrado chi2, p_val, dof, expected = st.chi2_contingency(tabla) print(f"\nEstadístico χ²: {chi2:.2f}") print(f"Grados de libertad: {dof}") print(f"Valor p: {p_val:.6f}") if p_val < 0.05: print("✅ RECHAZAMOS H₀: Hay asociación significativa.") else: print("❌ NO rechazamos H₀.") # Visualizar residuos (dónde está la asociación) residuos = tabla - expected sns.heatmap(residuos, annot=True, fmt=".0f", cmap="RdBu_r", center=0) plt.title("Residuos: Observado − Esperado") plt.show()
